# Ultra X Spring 50km: shared training tracker

A static site, rebuilt by GitHub Actions, that tracks Murray's and Rich's runs against a shared, distance-based
26-week plan for the **Ultra X Spring Trail Series 50km on Saturday 17 April 2027**, and adjusts the upcoming long runs
from what was actually run. Run data comes from Apple Health, sent by an iPhone Shortcut each week.

```
iPhone Shortcut --> repository_dispatch --> scripts/ingest.py --> runs/<athlete>.json (committed)
runs/*.json --> scripts/load_runs.py --> scripts/adapt.py (rules) --> scripts/commentary.py (optional Claude note)
                                                                 \--> scripts/build_site.py --> GitHub Pages
```

* `config/plan.json` is generated by `scripts/make_plan.py`. Edit the tables at the top of that file to change the plan.
* To move a cutback week: `python scripts/make_plan.py --swap 6 7`, commit and push.
* `config/overrides.json` flags a niggle (cuts the next three long runs by 25%) or forces a distance for a week.
* The adjustment rules are at the top of `scripts/adapt.py` and on the site.
* Resting HR and HRV are not uploaded and not published.

## One-off setup
1. **Settings > Pages > Source: GitHub Actions.** Rich needs write access: **Settings > Collaborators > add Rich.**
2. Each athlete creates a fine-grained token at <https://github.com/settings/personal-access-tokens/new>:
   *Only select repositories* > this repo, permission **Contents: Read and write**, 1-year expiry. Keep it private; it goes only into their own Shortcut.
3. Each athlete builds the weekly Shortcut (see `SHORTCUT.md`) and sets it to run automatically on Sunday 19:00.
4. Optional: add an `ANTHROPIC_API_KEY` repository secret to enable the weekly Claude coaching note.
5. **Actions > Update training site > Run workflow** for the first build. Site: `https://<username>.github.io/<repository>/`.

## Weekly check-ins (ticks and notes)
Each athlete's tab has a week check-in card: tick Run A/B and the long run, add a note (max 280 characters), then Save. Signing in uses the same GitHub token as the upload Shortcut, kept in that browser's localStorage. Saves are commits to `log/checkins.json`, so notes are public and ticks never change the plan. The site rebuilds after each save.

## Backfilling history
`runs/<athlete>.json` holds the run history. To load older runs, send the same payload the Shortcut sends:
`PAYLOAD="$(cat backfill.json)" python scripts/ingest.py`, then commit `runs/`.

## Apple Health readiness check
`python scripts/health_summary.py path/to/export.xml my_health_summary.csv` makes a small private summary (resting HR, HRV, runs).
Share it privately for the Claude plan. Do not commit it.


## Privacy
* **GitHub Pages sites are public**: dates, distances, durations and average heart rates of every run are visible to anyone with the link. No routes or GPS data are uploaded.
* Never commit tokens, `export.xml` or the Health summary CSV. If a token leaks, revoke it in GitHub settings.

## Limits
* Weather, sleep and illness are not seen: use `config/overrides.json`.
* Rules adjust long-run distance. Weekday sessions get plain-language suggestions only.
* General training guidance, not medical advice.
